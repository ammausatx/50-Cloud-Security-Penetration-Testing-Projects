# Contributing

1. Use only cloud environments you own or are explicitly authorized to assess.
2. Prefer read-only commands and non-destructive validation.
3. Never include credentials, access tokens, private keys, customer data, or unredacted identifiers.
4. Clearly label fabricated screenshots and outputs as **SIMULATED**. Never present them as live evidence.
5. Include prerequisites, exact scope, tool versions, steps, expected observations, remediation, and cleanup.
6. Document permission gaps and coverage limitations honestly.
7. For advanced attack-path topics, use isolated lab tenants and safe simulations; do not provide instructions for compromising third-party environments, persistence, or real data theft.
